# 웨더 퀘스트

모바일 중심 반응형 개인 옷차림 추천 웹. 기존 nihongo-quest와 별도 프로젝트입니다.

## Vercel + Supabase 배포

[단계별 설정 안내](docs/DEPLOY.md)를 따라 Supabase에서 `supabase/schema.sql`을 실행하고 Vercel에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 등록하세요. Vercel에서는 Supabase만 사용하며 DB 설정 누락 시 임시 로컬 저장으로 대체하지 않습니다. 로컬에서만 환경변수가 없으면 SQLite로 실행합니다.

## 실행

Node.js 24 이상에서 추가 패키지 설치 없이 실행합니다.

```powershell
cd D:\BuyRawFish\weather-quest
npm start
```

PC: http://localhost:3002. 같은 Wi-Fi의 모바일·태블릿: `http://PC의내부IP:3002`. 서버가 켜져 있어야 하며 Windows 방화벽에서 해당 포트 접근이 허용되어야 합니다. 인터넷 공유는 별도 서버 배포가 필요합니다.

`PORT`, `HOST`, `DATA_DIR` 환경변수로 포트, 바인딩 주소, DB 폴더를 변경할 수 있습니다. 기본 DB는 `data/weather.sqlite`입니다. 재배포 시에도 이 폴더를 영구 볼륨에 유지하세요. 실행 중 DB 백업은 JSON 내보내기를 사용하세요.

## 구현 범위

- 닉네임으로 프로필 생성/재접속. 앞뒤 공백, 유니코드 표준화, 영문 대소문자를 통일합니다. 인증이 아니며 닉네임을 아는 사람은 수정할 수 있습니다.
- 서울·부산·인천·대구·대전·광주·제주, 현재 기온·일별 최저/최고와 3시간 간격 날씨 표(기온·체감·강수확률·바람), 오늘/내일 아침 비교. 모바일 표는 내부 가로 스크롤을 지원합니다. Open-Meteo 데이터를 서버에서 받아 10분 캐시하며 실패 시 가짜 날씨를 표시하지 않습니다.
- 추위/더위 민감도, 외출 시각, 활동량 설정.
- 상의·중간옷·겉옷 조합의 상대 보온 점수. 실제 착용과 5단계 피드백으로 공통 보정값을 서서히 조정합니다. 실내 기록은 보정에서 제외합니다.
- 추천 조합에서 옷 추가·제거, 소재·두께 변경, 실시간 보온 합계/목표 비교, 실제 착용 기록에 적용. 오늘·내일의 조합은 독립적으로 유지합니다. 모바일에서는 선택 중 합계 표시가 상단에 고정됩니다.
- 셔츠·니트·후드집업·코트·패딩을 두께·기모·안감·충전 부피로 세분화하며 플리스를 추가했습니다. [보온 분류 근거와 한계](docs/WARMTH.md)를 참고하세요. 새 기록에는 선택한 세부 분류와 점수를 저장하고 기존 기록의 표시 점수는 유지합니다.
- 배포 서버는 Supabase, 환경변수 없는 로컬은 SQLite에 저장합니다. 브라우저에는 마지막 닉네임만 보관합니다. 동일 프로필은 재접속/새로고침 시 최신 기록을 불러옵니다. 실시간 화면 자동 갱신은 아직 없습니다.
- 날짜별 한 기록: 서버가 저장 ID를 `day:YYYY-MM-DD`로 정규화해 동일 날짜 재저장은 갱신합니다. 기존 중복은 날짜별 최신 기록 하나로 읽고 수정 저장 시 해당 날짜의 구형 중복 행을 정리합니다. 새 DB 스키마 실행은 필요하지 않습니다. 기록의 수정 버튼으로 조합·체감·장소를 변경할 수 있으며, 과거 기록의 날씨와 시각은 유지합니다.
- JSON 전체 내보내기, 가져오기 전 미리 확인 및 백업 다운로드, 새 날짜의 기록만 병합. 이미 있는 날짜의 기록과 설정은 덮어쓰지 않습니다. 전체 교체 복원과 수정 충돌 선택 UI는 후속 작업입니다.

초기 추천 공식: `1 + (26 - 체감온도) × 0.3`을 1~12로 제한하고 개인·활동 보정을 반영합니다. 과학적 보온 척도가 아닌 초기 가설입니다. 개인 보정은 실외 착용 기록을 시간순으로 반영하며 이전 값 80%, 새 추정값 20%로 조정합니다.

날씨: [Open-Meteo](https://open-meteo.com/), [API 문서](https://open-meteo.com/en/docs). 기록하는 날씨는 관측 실황이 아닌 해당 시간의 예보입니다. 정밀한 내 옷장, 애니메이션 캐릭터, 기록 수정·삭제, 하의 점수 학습은 아직 포함하지 않았습니다.

## 검증

```powershell
npm test
```

추천 방향성·레이어 구성·실내 피드백 제외, 서버 API·DB 재시작 영속성·중복 병합·잘못된 파일 거부를 검증합니다.

Windows에 Chrome이 설치된 환경에서는 `node scripts/browser-check.mjs`로 실제 브라우저 조합·두께 변경·저장·오늘/내일 전환 및 390/768/1440px 가로 넘침 검사를 실행할 수 있습니다. QA는 별도 임시 DB를 사용하며 화면 캡처는 Git에서 제외된 `.qa/`에 저장합니다.
