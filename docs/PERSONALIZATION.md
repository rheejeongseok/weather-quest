# 개인별 예상 보온 범위

예상 범위는 실제 착용 기록을 해석하는 앱의 비교용 안내입니다. 통계적 신뢰구간, 건강·체질 진단, 제품의 실측 보온 성능 또는 검증된 적정 의복량을 의미하지 않습니다.

## 1. 옷 점수와 개인 범위를 분리

옷 종류·소재·두께별 점수는 이번 변경에서 고정했습니다. 사용자의 피드백으로 옷 점수와 개인 민감도를 동시에 바꾸지 않습니다. 개인의 편안한 범위만 조정합니다. 현재 `scoreVersion`(3) 기록은 저장한 점수를 사용하고, 이전 점수 체계의 기록은 저장된 소재·두께 선택으로 현재 분류에 맞춰 환산해 참고합니다(`WARMTH.md`). 기존 기록 자체를 덮어쓰지 않습니다.

## 2. 비교할 기록 선정

- 기록의 기준 체감온도는 **관측 보정값 → 외출 시간대 예보 평균 → 기록 시각 예보** 순서로 사용합니다(아래 9절).
- 같은 기온대의 범위 계산(3·4절)은 현재 추천 시간의 체감온도와 ±5℃ 이내인 실외 기록만 사용합니다. 그보다 먼 기록은 6절의 빠른 추정에만 씁니다.
- 삭제·실내·잘못된 피드백·기온 차이가 큰 기록은 제외합니다.
- 날짜별 최신 기록 하나만 사용합니다. 수정으로 같은 기록의 영향력이 늘지 않습니다.
- 온도 차이는 3℃ 폭의 가우시안 가중치를 사용합니다.
- 활동량이 다르면 가중치 0.5, 야외 체류 시간이 다르면 0.65를 곱합니다. 관련 정보가 없는 이전 기록은 각각 0.8, 0.85를 곱합니다. 가중치는 초기 설계값입니다.
- 상의 점수만으로 비교하기 어려운 기록은 비중을 낮춥니다. 외출 중 체감이 바뀐 기록 0.5, 중간에 옷을 벗거나 더 입은 기록 0.6, 보통이 아닌 하의나 소품을 착용한 기록 0.75를 곱합니다. 점수를 더하거나 빼지 않으며, 이 값도 초기 설계값입니다.
- 당시 기온·활동량·체류 시간의 앱 보정을 제거하고, 현재 조건의 보정을 더해 기록의 점수를 비교합니다. 기온 보정은 기본 기준식과 같은 1℃당 0.3점입니다. 예를 들어 10℃에서 6점이 조금 추웠다면 15℃에서는 4.5점보다, 5℃에서는 7.5점보다 따뜻하게 입어야 한다는 근거가 됩니다. 이 보정도 실증 계수가 아닌 앱 가정입니다.

## 3. 적당했던 기록을 기준점으로 사용

‘적당했어요’ 기록의 가중 중앙값과 25~75% 분위수를 기준으로 범위를 형성합니다. 이상값에 덜 민감하게 중앙값을 사용합니다. 최소한의 여유 폭을 두고 0.5점 단위로 바깥쪽 반올림합니다.

기준점의 유효 가중치 합을 2로 나눈 값을 최대 1까지 사용해 임시 중심과 기록 중심을 혼합합니다. 두 개라는 기준은 정확도를 보장하는 표본 수가 아니라 초기 표시·혼합 규칙입니다. 조건이 다르거나 온도 차이가 있으면 같은 기록 개수라도 비중이 줄어듭니다. 기록 수를 정확도 백분율로 표시하지 않습니다.

충분한 비중의 적당했던 기록이 있으면 임시 공식보다 실제 착용 점수가 우선합니다. 학습한 범위를 기존 임시 목표의 12점 상한에 억지로 맞추지 않습니다. 입력 오류 방지를 위한 전체 비교 범위는 0.5~30점입니다.

## 4. 추움·더움은 방향 정보

‘추웠어요’는 그 조합보다 따뜻한 방향, ‘더웠어요’는 그 조합보다 가벼운 방향의 근거로 사용합니다. 체감 한 단계마다 0.8점처럼 일정한 점수로 변환하지 않습니다.

해당 방향 기록의 가중 중앙값에서 다음/이전 0.5점 단계로 경계를 설정합니다. 그 경계가 다른 방향이나 적당했던 기록과 충돌하면 좁은 범위를 강제로 확정하지 않습니다. 점수 간격 자체는 편의상 정한 앱의 해상도입니다.

## 5. 화면의 기록 상태

| 상태 | 뜻 |
| --- | --- |
| 임시 기준 | 비교 가능한 기록이 없어 기본 가정과 설정을 사용 |
| 기록으로 추정 | 비슷한 기온의 기록은 없지만 다른 기온(15℃ 이내)의 기록으로 대략적인 기준을 추정 |
| 기록을 알아가는 중 | 적당했던 근거가 있으나 아직 적어 임시 기준도 혼합 |
| 개인 기록 기준 | 비슷한 조건의 적당했던 기록이 주된 기준 |
| 착용감 방향만 참고 | 적당했던 기록 없이 추움·더움 방향만 확인 |
| 기록이 엇갈려요 | 비슷한 조건의 응답이 충돌해 확정적으로 안내하지 않음 |

모든 상태가 ‘정확함’을 뜻하는 것은 아닙니다. 화면에서 참고한 날짜, 실제 옷, 착용 점수, 체감온도와 피드백을 확인할 수 있습니다. 가장 관련 있는 기록을 먼저 보여주고 나머지는 접어서 표시합니다. 적당했던 조합은 버튼으로 다시 불러올 수 있습니다.

## 6. 출발점과 빠른 추정

기본 기준식 `1 + (26 - 체감온도) × 0.3`(1~12로 제한)에 개인 차이(아래), 활동량, 야외 시간 보정을 더한 값이 출발점입니다. 기온별 표준을 관찰 데이터로 학습한 식은 아닙니다.

**설정의 민감도:** 추위·더위 민감도는 한 단계 1점(≈0.1 clo), 최대 ±2점씩입니다. 추위는 추운 날(체감 8℃ 이하)에, 더위는 더운 날(20℃ 이상)에 전부 반영하고, 반대 계절에도 절반을 반영합니다. 더위를 타는 사람은 겨울에도 덜 껴입는 경향을 반영한 것입니다. 사람마다 차이가 크다는 전제로 효과를 크게 잡았고, 기록이 쌓이면 기록이 우선합니다.

**빠른 추정:** 기록이 한두 개뿐이어도 대략적인 기준을 잡기 위해, 기록마다 '기본 기준식보다 몇 점 더(덜) 입는 사람인지'를 계산해 다른 기온에도 옮겨 씁니다.

- 적당했어요는 그 점수, 조금 추웠어요/더웠어요는 ±1점, 많이 추웠어요/더웠어요는 ±2점을 필요 보온으로 봅니다. 이 환산은 빠른 추정에만 쓰고, 같은 기온대의 범위 경계(4절)는 계속 방향 정보로만 씁니다.
- 비중은 적당 1, 조금 0.7, 많이 0.5에 비교 가능성 가중치를 곱하고, 기온 차이에 따라 8℃ 폭의 가우시안으로 줄입니다. 15℃ 넘게 차이 나는 기록은 쓰지 않습니다(겨울 기록으로 여름을 추정하지 않음).
- 설정에서 나온 개인 차이를 기록 1개만큼의 비중으로 섞습니다. 그래서 같은 기온의 기록 1개면 기록이 말하는 차이의 절반, 2개면 약 2/3만큼 이동합니다.
- 추정 범위 폭은 ±1점에서 시작해, 기록 비중이 쌓일수록 ±0.5점까지 좁아집니다.

이 값들(1점 환산, 8℃ 폭, 15℃ 한도, 설정 비중 1)은 모두 초기 설계값이며, 추천 확인 통계로 검증해야 합니다.

실제 기록이 쌓이면 임시 공식에 대한 작은 보정만 하는 대신, 적당했던 착용 점수 자체로 기준을 옮깁니다. 옷별 점수는 계속 고정합니다.

## 7. 스타일과 조합

같은 보온 점수의 조합은 매우 많아서 점수만 맞추면 "반팔 + 울 코트"처럼 어색한 조합이 나올 수 있습니다. 그래서 옷·선택지별로 흔히 입는 체감온도 범위(`apps/cloth/lib.mjs`의 `seasonBands`)를 두고, 범위를 벗어난 정도에 따라 1℃당 0.06(최대 0.6)의 작은 비용을 더합니다. 범위를 벗어나는 보온 비용(1점당 5)보다 훨씬 작아 필요한 보온량은 바꾸지 않습니다. 실제로 입고 적당했던 조합에는 이 비용을 적용하지 않아 개인 기록이 우선합니다. 계절 범위는 검증된 값이 아닌 앱 가정입니다.

자동 추천은 범위 밖의 차이를 먼저 줄이고, 범위 안에서는 겹 수(적게/보통/여러 겹), 이너 선호, 주로 입는 겉옷, 즐겨 입는 상의 취향을 작은 가중치로 반영하고, 추천에서 뺄 옷은 후보에서 제외합니다. 취향 가중치는 범위를 벗어나는 비용보다 훨씬 작아 필요한 보온량을 바꾸지 않습니다. 비슷한 스타일과 보온 범위에 맞는 실제 편안했던 조합도 추천 후보로 참고합니다. 바람 차단은 별도로 고려합니다.

수동 조합은 범위 아래/안/위 중 어디에 있는지 비교합니다. 내부 정렬을 위한 중심점은 남지만 화면에서 정밀한 정답 점수처럼 강조하지 않습니다.

## 8. 삭제와 검증

삭제·수정 후 범위는 남은 기록으로 다시 계산합니다. 삭제 표시는 이전 중복이나 백업의 재생성을 막고, 옷·날씨·피드백 본문을 남기지 않습니다. 같은 날짜에 사용자가 명시적으로 다시 기록할 수 있습니다.

자동 테스트는 관측값 우선 사용, 비교 가능성 가중치, 추천 스냅샷 판정, 관측 보정 수집, 임시 상태, 적당함 기준점, 추움·더움 경계, 상충 응답, 먼 기온·실내·삭제 제외, 날짜 중복, 활동·체류 시간 가중치, 추천·수동 비교의 범위 일치를 검증합니다. 브라우저에서는 임시 상태에서 개인 기록 기준으로 전환, 근거 표시·조합 불러오기, 기기별 레이아웃도 확인합니다.

실제 추천 정확도는 학습에 쓴 기록을 재평가하는 대신 이후의 외출 피드백에서 적당함 비율과 심한 추움·더움 비율로 확인해야 합니다.

## 9. 기록에 함께 저장하는 데이터

범위 계산의 입력을 정확하게 하고, 추천 정확도를 나중에 확인하기 위한 데이터입니다. 기존 기록에는 값이 없으며(null) 그대로 동작합니다. DB 스키마 변경은 필요하지 않습니다.

| 필드 | 내용 | 사용처 |
| --- | --- | --- |
| `weather.window` | 외출 시작·종료 시각, 그 사이 예보 체감의 최저·최고·평균 | 기준 체감온도, 관측 보정 구간 |
| `weather.rain`, `weather.cloud`, `weather.radiation` | 강수확률, 운량, 일사량 예보 | 저장만(향후 분석용) |
| `observed` | 지난 날짜의 외출 시간대 Open-Meteo 과거 시간별 값: 기온·체감(평균·최저·최고)·바람·운량·일사량·강수량 | 기준 체감온도 1순위 |
| `swing` | 내내 비슷 / 나중엔 추움 / 나중엔 더움 | 비교 가능성 가중치 |
| `layerChange` | 그대로 / 벗음 / 더 입음 | 비교 가능성 가중치 |
| `bottom`, `accessories` | 하의 3단계, 목도리·장갑·모자 | 비교 가능성 가중치 |
| `recommendation` | 기록 당시 보여준 범위·중심·상태·추천 조합, 착용 조합의 범위 아래/안/위(`rangeResult`), 추천 그대로 착용 여부(`followed`) | 추천 확인 통계 |

### 관측 보정

프로필을 불러올 때 오늘 이전의 실외 기록 중 `observed`가 없는 최근 92일 이내 기록(최대 31개)을 찾아, 지역별로 Open-Meteo `past_days` 시간별 값을 한 번 받아 외출 시간대 평균으로 채웁니다. 이 값은 관측소 실측이 아니라 지난 시각에 관측을 반영해 다시 계산된 모델 값입니다. 실패하면 기존 예보 값을 그대로 사용하며 로그인에는 영향을 주지 않습니다. 지역 데이터는 서버 메모리에 하루 단위로 캐시합니다. `WQ_OBSERVED=off`로 끌 수 있습니다(테스트·브라우저 검사에서 사용).

### 추천 확인

오늘 기록을 처음 저장할 때, 그 날짜의 기록을 제외하고 계산한 추천을 함께 저장합니다. 같은 날짜를 수정해도 처음 저장한 추천은 바뀌지 않습니다. 기록 관리 화면에는 추천을 저장한 실외 기록 중 적당했던 비율, 추천 범위 안으로 입은 날의 적당 비율, 많이 춥거나 더웠던 날 수를 표시합니다. 학습에 쓴 기록을 다시 채점한 값이 아니라 당시 추천과 이후 착용감의 비교이며, 기록이 적을 때는 비율의 변동이 큽니다.
